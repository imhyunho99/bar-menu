# 메뉴판 레이아웃을 손님 화면에 실제로 그린다

작성 2026-09-12. 대상 브랜치 `develop`.
선행: `2026-09-12-manual-transfer-gate-design.md` (결제가 먼저 나간다).

## 지금 상태 — 저장은 되는데 아무도 안 그린다

2026-09-12 에 로컬에서 전 구간을 확인했다.

| 단계 | 결과 |
|---|---|
| 위젯 렌더링 | O 카테고리 3개·메뉴 5개 컴포넌트 박스가 %좌표로 그려짐 |
| 드래그 | O `y: 70 → 62.56`, 박스 style 과 숨은 textarea 가 함께 갱신 |
| 인스펙터(표시·X·Y·W·H) | O "화면에 표시" 해제 → JSON 이 `visible: false` 로 |
| 저장 | O DB 반영 |
| API 전송 | O `/api/v1/restaurants/<slug>/` 응답에 실림 |
| **손님 화면** | **X 아무 변화 없음** |

`category_name` 을 `visible: false` 로 저장하고 손님 화면을 다시 열었는데
"안주"·"주류"·"식사"가 그대로 `display: block` 으로 보였다. 카드 DOM 은 이렇다.

    <a class="category-card">
      <p class="category-name-en">Anju</p>
      <h3 class="category-name-ko">안주</h3>
    </a>

`position: static` 이고, 레이아웃 JSON 이 "보이라"고 지정한 `category_image` 는
요소조차 없다. Django 가 그리는 `/{slug}/` 도 마찬가지다(거기는 접히는 목록형이라
카드 개념 자체가 없다). `menu_card_layout_json` 도 같다.

`git log -S "card_layout_json"` 을 템플릿·프론트에 걸면 커밋이 하나도 없다.
필드를 만든 커밋(`5707fe6`)은 있는데 그리는 쪽을 만든 커밋은 없다. 처음부터
연결된 적이 없다.

데이터는 있다. `Category.category_image` 와 `MenuItem.menu_image` 둘 다 직렬화되어
나가고 `frontend/src/lib/types.ts` 에도 이미 있다. 카드가 안 그릴 뿐이다.

## 1. 언제 레이아웃을 쓰는가 — `layout_type` 이 스위치다

JSON 에 `layout_type: "default"` 가 들어 있는데 아무도 안 읽는다. 그것을 그대로
쓴다. 빌더에서 실제로 무언가를 옮기면 `"custom"` 이 되고, **그때만** 절대배치
렌더러가 돈다.

이건 선택이 아니다. 스위치 없이 켜면 배포하는 순간 `bid`·`sorok` 을 포함한 모든
매장의 손님 화면이 바뀐다. 파트너 매장은 건드리지 않는다. 새 필드도 마이그레이션도
필요 없다.

## 2. 카드에 높이를 준다

x/y/w/h 가 %인데 지금 카드는 내용만큼 늘어난다. 절대배치는 높이가 정해져야
성립한다. 빌더 캔버스가 322×242(≈4:3)이므로 카드에 같은 `aspect-ratio` 를 준다.
그래야 빌더에서 본 것과 손님이 보는 것이 같아진다 — WYSIWYG 의 전제다.

비율을 빌더와 렌더러 두 곳에 적으면 언젠가 갈린다. 상수 하나를 두고 양쪽이
그것을 읽는다. 갈리면 테스트가 먼저 깨지게 한다.

## 3. custom 이면 빌더가 전권을 갖는다

`MenuCard.tsx`(257줄)는 `display_mode`(`auto`/`image_only`/`text_only`/`combined`)
네 갈래로 이미 그린다. 게다가 빌더가 모르는 것을 더 그린다: `notes`, 장바구니
버튼, 상세보기, 이미지 라이트박스.

`layout_type == "custom"` 이면 `display_mode` 를 무시하고 배치를 빌더가 전부
결정한다. 주인이 둘이면 "이미지를 보이게 놓았는데 안 나온다"가 생기고, 그걸
설명할 자리가 화면에 없다.

**그래서 빌더에 컴포넌트를 추가해야 한다.** 지금 메뉴 카드 컴포넌트는 5개
(이미지·한글명·영문명·가격·설명)뿐이라, 이대로 전권을 주면 custom 을 켜는 순간
`notes` 와 장바구니 버튼이 사라진다. 그건 수리가 아니라 새 사고다. 최소한
`menu_notes` 와 `cart_button` 을 더한다.

상호작용은 배치가 아니므로 컴포넌트에 붙여 둔다 — 이미지 컴포넌트에 라이트박스,
카드 전체에 상세보기. 레이아웃이 바뀌어도 그 성질은 따라다닌다.

`layout_type == "default"` 인 매장은 오늘 코드 그대로 돈다. 두 경로가 한동안
공존한다.

## 4. 글자 넘침

고정 높이 상자에 긴 메뉴명이 들어가면 넘친다. 상자 안에서 줄 수를 제한하고
말줄임으로 자른다. **빌더 미리보기도 같은 규칙으로 그린다** — 사장님이 잘린 것을
저장 전에 봐야 한다. 여기가 갈리면 WYSIWYG 이 거짓이 된다.

## 5. 빌더 자체 결함

2026-09-12 에 드러난 것 둘.

- 박스를 다른 박스 위에 정확히 포개면 아래 박스를 다시 고를 수 없다. 선택된
  박스가 `z-index: 10` 으로 덮는다. 같은 자리를 다시 누르면 겹친 것들을 돌아가며
  고르게 하거나, 컴포넌트 목록에서 고르게 한다.
- mousedown 후 1px 만 움직여도 드래그로 처리된다. 임계값(4px 정도)을 둔다.
  임계값이 없으면 '고르려던 클릭'이 늘 '옮김'이 된다.

## 6. 테스트 — 지금 0개다

- 직렬화 계약: `layout_type` 이 `custom` 일 때만 렌더러가 도는지
- 렌더러: 레이아웃 JSON → 카드 DOM. `visible: false` 면 요소가 **없는지**,
  x/y/w/h 가 style 에 박히는지
- 빌더: 드래그가 textarea 를 갱신하는지, 겹친 박스를 다시 고를 수 있는지,
  임계값 아래 움직임이 드래그가 아닌지
- E2E: 2026-09-12 에 손으로 한 것을 자동화한다 — 빌더에서 숨김 → 저장 →
  손님 화면에서 사라짐. **이 테스트가 있었으면 이 구멍은 애초에 안 생겼다.**

## 순서

1. `layout_type` 스위치와 직렬화 계약 (렌더러 없이, 테스트만)
2. 카테고리 카드 렌더러 — 컴포넌트가 3개뿐이라 여기서 규칙을 굳힌다
3. 메뉴 카드 렌더러 + 빌더 컴포넌트 추가(`menu_notes`·`cart_button`)
4. 빌더 결함 수리
5. E2E

2 까지 가면 손님 화면에 처음으로 레이아웃이 닿는다. 거기서 한 번 멈추고 실제
매장으로 확인한 뒤 3 으로 간다.
