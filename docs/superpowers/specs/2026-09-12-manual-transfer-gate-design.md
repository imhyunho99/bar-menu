# 계좌이체 수동 확인 게이트 — 미리보기는 무료, 발행은 결제 후

작성 2026-09-12. 대상 브랜치 `develop`.

## 무엇을 바꾸는가

돈 받는 경계를 옮긴다. 지금은 "가입 후 7일은 손님 화면까지 열리고, 그다음 닫힌다"
인데, 앞으로는 **기한 없이 미리보기까지 무료이고 손님 공개만 유료**다. 청구는
계좌이체로 받고 확인은 사람이 한다.

POS 연동은 검토했으나 이번에는 하지 않는다. 카카오페이는 계속 잠들어 있다
(`PAYMENT_PROVIDER` 미설정). 코드는 그대로 두므로 심사를 받게 되면 키만 넣으면
이어지고, 이 수동 경로와 나란히 살 수 있다.

## 무료의 경계

| | 무료 (`unpaid`) | 입금 확인 후 (`active`) |
|---|---|---|
| 메뉴·카테고리 등록/수정 | O | O |
| 디자인 (로고·색·폰트) | O | O |
| 자기 메뉴판 보기 | 미리보기 링크 (워터마크·24시간) | 진짜 손님 주소 |
| 손님 URL·API | X (402) | O |
| QR 발행 | X | O |
| 사진으로 메뉴 등록 | 1회 | 무제한 |
| 주문 기능 | (손님 화면이 닫혀 자동으로 무의미) | O |

## 상태 기계

새 상태를 만들지 않는다. `unpaid` 가 이미 "결제 전"을 뜻하고, 이제 그것이 곧
무료 미리보기 계정이다. 바뀌는 것은 **가입 시 기본값**뿐이다.

- `models.py` 의 `create_restaurant_settings` 시그널: `status='trialing'` → `'unpaid'`,
  `current_period_end` 를 채우지 않는다.
- `trialing` 상태와 `TRIAL_DAYS` 를 지운다. 마이그레이션이 남아 있는 `trialing`
  행을 `unpaid` 로 내린다. 운영의 `bid`·`sorok` 은 `partner` 라 영향이 없다.
- `is_usable()` 은 한 줄도 고치지 않는다. `unpaid` 는 이미 False 를 준다.
  '상태 먼저, 날짜 나중' 이라는 성질을 `tests_subscription_gate.py` 가 못박고
  있으므로 거기도 건드리지 않는다.

`never_opened` 판정은 그대로 둔다. `unpaid` 는 여전히 '한 번도 연 적 없음'이고,
결제했다가 기간이 지난 매장은 `status='active'` 에 날짜만 과거라 '닫힘'으로
읽힌다. 두 문구가 갈리는 이유는 전자에 '잠시 후 다시'라고 하면 열릴 리 없는
화면을 계속 새로고침하기 때문이다.

## 미리보기 링크

`django.core.signing.TimestampSigner` 를 쓴다. HMAC 을 손으로 짜지 않고 Django
표준 도구로 끝난다. 새 모델도 필드도 마이그레이션도 없다.

`menu/preview.py` 에 함수 둘만 둔다.

    make_preview_token(slug) -> str
    check_preview_token(slug, token) -> bool      # 수명 24시간

서명에 slug 가 들어가므로 남의 매장 토큰으로는 열리지 않는다.

**게이트**: `SubscriptionGateMiddleware` 가 402 를 내기 **직전에** 토큰을 본다.
유효하면 통과시킨다.

**발급**: 관리 대시보드와 온보딩 체크리스트에 "미리보기 열기 / 링크 복사".
누를 때마다 그 자리에서 새로 만든다. 저장하지 않으니 회전을 신경 쓸 일이 없다.

**워터마크**: 화면 최상단 고정 바 — "미리보기입니다 · 손님에게는 아직 보이지
않습니다". 닫기 버튼 없음. 손님 화면(Next.js)은 `searchParams` 의 `preview`
유무로, Django 쪽 `/{slug}/` 는 템플릿 include 로 같은 바를 그린다.

**왜 DB 토큰이 아닌가**: 즉시 무효화가 되는 대신 회전을 사람이 눌러야 하고,
누른 적 없으면 그 링크는 영원히 산다. 무효화 기능이 있는데 아무도 안 쓰는
상태가 제일 나쁘다. 지금 막으려는 것은 공격이 아니라 "결제 안 하고 이 링크로
장사하기"이고, 그건 24시간 만료와 워터마크로 실용성이 사라진다. 나중에 DB
토큰이 필요해지면 위 함수 둘만 바꾸면 된다.

토큰이 만료되면 402 → 기존 `MenuNotOpen` 화면이 뜬다. 사장님은 관리 화면에서
다시 누르면 된다.

## QR 차단

지금은 `OWNER_PREFIXES` 에 `qr/` 가 있어 게이트를 **통과**한다. 그것을 빼는
것만으로는 부족하다 — 미들웨어는 손님용 '준비 중' 화면을 그리는데, QR 페이지를
보는 사람은 사장님이다.

차단은 `qr_views.generate_qr_code` 안에서 한다. 미결제면 QR 을 그리지 않고
사장님용 안내를 낸다: "입금이 확인되면 QR 이 발행됩니다" + 계좌·금액 + 입금
신청 버튼.

이 뷰에 `login_required` 와 매장 권한 검사를 함께 붙인다. **지금은 아무나 남의
`/{slug}/qr/` 를 열 수 있다.**

같이 고쳐야 하는 거짓말이 둘 있다. 온보딩 체크리스트의 'QR 받기' 단계 문구와,
미들웨어 주석·결제 화면의 "결제 전에도 QR 준비까지 된다"는 안내다. 지금 방침과
정반대라 그대로 두면 사장님이 속는다.

## 입금 신청과 확인

새 모델 `PaymentRequest`("입금 신청").

    restaurant · plan · depositor_name(입금자명) · amount
    status(pending/confirmed/rejected) · created_at · confirmed_at · confirmed_by · note

**사장님 쪽** — 결제 화면(`admin/billing/`)에 계좌번호·예금주·금액을 띄우고,
폼은 입금자명과 요금제 둘뿐이다. 보내면 `PaymentRequest` 가 남고 Discord 알림이
간다(기존 `DISCORD_WEBHOOK_URL` 재사용, 새 env 없음). 이후 화면은 "확인 중"으로
바뀌고, 대기 중인 신청이 있으면 또 못 보낸다 — 같은 입금이 두 줄로 남으면
통장과 대조할 때 헷갈린다.

계좌 정보는 코드에 박지 않고 `.env` 에 둔다: `BANK_NAME`·`BANK_ACCOUNT`·`BANK_HOLDER`.

**확인하는 쪽** — Django admin 의 입금 신청 목록에 액션 넷: `1개월 확인` /
`3개월` / `6개월` / `1년`. 기간 입력 페이지를 따로 거치지 않는다. 누르면
`Subscription.status='active'`,
`current_period_end = max(지금, 기존 만료일) + 기간`.
기존 만료일을 보는 이유는 만료 전에 미리 낸 사람의 남은 날을 먹지 않기 위해서다.

**만료** — `expire_trials` 를 지우고 `sweep_subscriptions` 를 그 자리에 둔다.
하루 한 번 돌며 만료 7일 전에 사장님과 우리 양쪽에 알리고, 지난 것은 `unpaid`
로 내리며 알린다. 이것을 `charge_subscriptions` 에 얹지 않는 이유는 그쪽 첫 줄이
`get_provider()` 이고 `PaymentNotConfigured` 를 만나면 통째로 `return` 하기
때문이다 — 대행사가 없는 지금 거기 섞으면 스윕이 아예 안 돈다.

## 사진 메뉴등록: 무료 1회

방식은 지금 그대로 둔다. 비전 API 를 켜지 않고 Discord 로 사진을 넘겨 사람이
정리한다. 자동 인식 검토 결과는 아래 "미뤄둔 것"에 적었다.

`Subscription.photo_import_count` 필드 하나를 더한다. 사진이 실제로 Discord 로
나갈 때 1 올린다. **한 번의 전송이 1회**다 — 장수로 세면 사장님이 나눠 보내야
하나 고민한다. `active`·`partner` 는 카운트를 보지 않는다.

카운터는 매장 평생 누적이고 **입금 확인이 되돌리지 않는다.** 결제했다가 기간이
지나 `unpaid` 로 돌아온 매장은 이미 1을 넘겼으므로 무료 1회가 다시 생기지 않는다.
'무료 1회'는 맛보기지 매달 주는 몫이 아니다. 다시 열어줄 일이 생기면 admin 에서
값을 0으로 내린다.

무료 매장이 1회를 쓰고 나면 화면이 안내로 바뀐다: "사진 등록은 1회 제공됩니다.
직접 입력은 계속 무료입니다." 막다른 길로 끝내지 않고 다음 행동을 준다.
알림에는 `[미결제]` 표시를 붙여 우선순위를 고를 수 있게 한다.

**결과가 즉시 나오지 않는다는 점을 화면이 말해야 한다.** 사진을 보낸 사장님은
우리가 손을 댈 때까지 미리보기가 비어 있다. 전송 후 화면과 미리보기 버튼 옆에
"보내주신 사진을 정리하는 중입니다. 그동안 직접 입력으로도 채우실 수 있습니다"
를 단다. 없으면 빈 미리보기를 보고 이탈한다.

**중계가 실제로 도는지 확인한다.** 코드는 `tests_menu_photo_relay` 16개가
통과하고 2026-08-23 에 실제 웹훅으로도 전송을 확인했지만, 지금 dev·운영 서버의
`DISCORD_WEBHOOK_URL` 이 살아 있는지는 확인되지 않았다(로컬 `.env` 에는 없다).
배포 전에 서버에서 확인한다.

## 테스트

`tests_trial.py` 는 통째로 사라지고 둘이 대신 들어온다.

- `tests_preview.py` — 토큰 위조·만료·남의 매장 토큰·워터마크 노출
- `tests_payment_request.py` — 중복 신청 차단, 기간 누적, 확인 후 QR 해제

마케팅 문구 대조 테스트는 **방향을 뒤집어 남긴다.** 지금은 "랜딩이 약속한 일수
== `TRIAL_DAYS`" 인데, 앞으로는 "가입 페이지 어디에도 `N일 무료` 문구가 남아
있지 않다"를 못박는다. `TRIAL_DAYS` 를 지우면 그 테스트는 자동으로 통과해
버리고, **문구만 남아 손님이 없는 체험을 약속받는 것**이 실제 사고다. 대상은
지금과 같은 4개 파일(`marketing-content.ts`, 랜딩·요금·가이드 `page.tsx`).

## 배포

develop 에서 충분히 QA 한 뒤 main 으로 올린다.

- `ENFORCE_SUBSCRIPTION` 기본값을 `True` 로 뒤집는다. 지금은 안 켜면
  `menu_is_live()` 가 무조건 True 라 전원이 공짜다. 예전에 "돈 낼 방법이 없다"가
  이유였지만 이제 계좌이체가 있고, 무료로 쓸 사람은 미리보기로 산다. 운영의
  `bid`·`sorok` 은 `partner` 라 영향이 없다. **잘못 배포하면 영업 중인 가게가
  꺼지는 쪽 스위치이므로 develop 에서 실제 매장 상태로 확인하고 올린다.**
- 서버 `.env` 에 `BANK_NAME`·`BANK_ACCOUNT`·`BANK_HOLDER` 추가
- cron 교체: `expire_trials` 제거 → `0 9 * * * sweep_subscriptions`
- 마이그레이션 3개: 상태 choices, `photo_import_count`, `PaymentRequest`

## 미뤄둔 것

**메뉴판 사진 자동 인식(비전).** 코드는 대부분 남아 있다 —
`menu_import.parse_menu_image`(구조화 출력), `shrink_for_vision`,
`admin/menu_import_preview.html`, `import_menu_commit`, 그리고 통과하는 테스트
7개. 비용도 걸림돌이 아니다: 2000px 사진 10장 기준 매장당 250~320원, 최악
560원. 껐던 이유인 "호출 상한이 없다"는 이 스펙의 1회/무제한 카운터가 이미
해결한다.

남은 진짜 걸림돌은 둘이다. `parse_menu_image` 가 **사진 한 장**만 받는데 사장님은
10장을 올린다(한 호출에 이미지 여러 개를 넣도록 고쳐야 한다). 그리고 그 한
호출이 길다 — 클라이언트 타임아웃이 120초인데 그 앞에 nginx 와 uwsgi harakiri 가
있어서, 사장님은 60초쯤에 502 를 보고 우리 코드의 친절한 타임아웃 메시지는
영영 뜨지 않는다. 동기로는 안 되고 백그라운드 + 폴링 화면이 필요하다.

결제 고객이 실제로 생긴 뒤에 켠다. 그때는 '무제한'을 파는 셈이라 자동화할 이유가
생기고 폴링 화면 만드는 값도 회수된다. 켤 때 `output_format=` 파라미터가
`output_config={"format": ...}` 로 바뀌었는지 확인할 것.

**메뉴판 레이아웃 렌더러.** 별도 스펙
(`2026-09-12-layout-renderer-design.md`). 이번 스펙보다 크고, 결제가 먼저다.
그때까지 무료 티어에서 레이아웃 빌더를 감춰 거짓말을 막는다.
